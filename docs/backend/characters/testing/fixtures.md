## Reference

### character_no_issues

**Type:** Character model instance

**Scope:** `function` (default)

**Returns:** Single `Character` instance without any related issues

**Dependencies:** None (creates data independently)

**Behavior:**
- Creates one Character using CharacterFactory
- Does not pass `add_issues` parameter, so no issues are created
- Character still has publisher and powers relationships (auto-generated by factory)
- Useful for testing characters that haven't appeared in any issues yet

**When to use:**
- Testing character detail endpoint with missing `first_issue`
- Testing character list filtering (characters without issues should be excluded by default)
- Testing character count endpoint (should not count characters without issues)
- Testing technical info endpoint with minimal relationships

**Usage examples:**

```python
def test_character_without_issues(api_client, character_no_issues):
    response = api_client.get(f"/api/characters/{character_no_issues.slug}/")
    assert response.data["first_issue_slug"] is None
    assert response.data["issues_count"] == 0
```

**Dependencies:** None (creates data independently)

**Behavior:**

- Each character has publisher and powers but no issues
- Useful for testing filtering behavior where these should be excluded

**When to use:**
- Testing `show-all=yes` filter on list endpoint
- Testing count endpoint with `show-all=yes` filter
- Testing default filtering behavior (these should not appear)
- Testing pagination with mixed data

**Usage examples:**

```python
def test_show_all_filter(api_client, characters_no_issues, characters_with_issues):
    # Without filter - should only show characters_with_issues
    response = api_client.get("/api/characters/")
    assert response.data["count"] == len(characters_with_issues)

    # With filter - should show both
    response = api_client.get("/api/characters/?show-all=yes")
    assert response.data["count"] == len(characters_no_issues) + len(characters_with_issues)
```

## Random Data Considerations

All fixtures use `randrange()` for varying data sizes:
- `characters_no_issues` and `characters_with_issues` create 2-9 items randomly
- `character_with_issues` creates 1-2 issues randomly

This randomization helps catch edge cases but may make debugging specific failures harder. For debugging, consider creating deterministic test data instead of using these fixtures.
